# CLAUDE.md

Personal website of Sarria (Qi Wang), live at https://sarria.ca.

## What this is

A hand-written static site: plain HTML, one CSS file, a few small JS files. No framework, no build step, no package manager. Open `index.html` in a browser or serve the folder with any static server. The only external dependency is three.js, loaded from jsDelivr by the `/cars` page through an import map.

## Deployment

- Hosted on **Vercel**, connected to this GitHub repo (`SarriaXD/blog_site`). Pushing to `master` deploys.
- `vercel.json` sets `framework: null`, no build or install command, and serves the repo root. `cleanUrls` is on, so `/tools` serves `tools/index.html`. `404.html` at the root is the custom not-found page.
- Nothing needs installing on Vercel. If the dashboard still shows a Next.js preset, `vercel.json` overrides it.

## Layout

- `index.html` — home, written as a film. Seven `[data-ch]` chapter sections (Intro, Craft, Stack, App, Chatbot, Cars, Contact), each `--len` viewports tall with a sticky `.ch__pin` holding its `.cap` captions (`data-at="a b"` is the slice of the chapter where a caption is visible). A fixed `<canvas id="film">` behind everything draws every frame in code; there are no images on the page. `.rail` is the chapter dot rail, `.timecode` the film counter, `.scroll-hint` the opening cue.
- `tools/index.html`, `tools/device-mockup/index.html` — tools index and the device mockup tool (POSTs to `https://api.sarria.ca/mockup-device`).
- `cars/index.html` — real-time studio render of the Tesla Model 3 (2024+ refresh, Premium trim; three.js). Full-viewport stage, a side rail of camera presets, paint swatches, specs below.
- `articles/index.html` — placeholder until articles exist.
- `linkedin/index.html` — meta-refresh redirect to LinkedIn.
- `404.html` — not found.
- `assets/css/style.css` — all styles. Design tokens live in `:root`. Breakpoints: 734px (phone) and 1068px (tablet).
- `assets/js/main.js` — nav menu, reveal-on-scroll, parallax (`data-parallax`), sticky scrolly sections (`data-scrolly`), carousel.
- `assets/js/film.js` — the home page film. Canvas 2D, no library. Scrolling is the playhead: `T` runs from 0 at the top of the first chapter to 7 at the end of the last, eased with a short lag for feel (snapped under `prefers-reduced-motion`). Each scene is a function of its local progress `t` (0–1 while the caption is pinned), its visibility `v` (neighbouring scenes cross-fade during the viewport where one caption scrolls out and the next scrolls in) and a clock for ambient motion. Scenes: prairie night with aurora and a skyline (Intro); phone, browser and server rack drawn stroke by stroke (Craft); the stack as a constellation (Stack); a phone running the driving test app with four screens on a streaming road (App); the chatbot window typing its replies (Chatbot); a blueprint side elevation of the Model 3 with rolling wheels and dimension lines (Cars); dawn over the same horizon (Contact). Drawing is in "units" (the shorter viewport side is 1000 units; `F.px` is one CSS pixel); line drawings are `Path` polylines so they can be traced partially; soft light goes on a low-res glow layer composited with `lighter`; a vignette and grain finish each frame. Captions are real HTML, faded by the script from the same scroll position.
- `assets/js/mockup.js` — device mockup tool only.
- `assets/js/cars.js` — the `/cars` scene: renderer, HDRI environment (at load the room is pulled down to black, keeping only the softboxes, because the Poly Haven studio's white cyclorama reflected in glossy paint reads as a pale sheet from the side; the ceiling goes too, lamps included, since two small lamps at the zenith of an equirect filter into a square; then what is left, the studio's own lamps, is blurred by about two degrees (`softenLights()`), because the two octagonal softboxes in the photo have honeycomb grids, a lattice of small bright squares that near-mirror glass reflects as a field of squares jumping at every triangle edge as the view turns, and the clearcoat shows beside its highlight; then our own softboxes, two long strips either side, a rim and a fill, are painted in as soft-edged ellipses in radiance (`paintLights()`, through the scene's environment rotation); then highlights are compressed so dark glass and lamp lenses don't blow out; the result goes in as half floats (`toHalf()`), because a 32-bit float texture cannot be linearly filtered on Apple GPUs and three.js samples it to build the reflection mips). The softboxes are not scene lights: a `RectAreaLight` is a hard-edged rectangle that the hood mirrors as a bright square from the angles a view change passes through, and painting them into the environment lets the paint's roughness filter them like the rest of the studio. glossy planar floor reflection (custom `Reflector` shader; `renderReflection()` runs the Reflector's pass and the blur pyramid at the top of each frame, before the main pass, because switching render targets mid-way through a multisampled pass makes tile-based mobile GPUs store and reload the whole MSAA buffer; the floor's own `onBeforeRender` is a no-op; the reflection pass clears to transparent so its alpha masks the car, keeps a depth texture, and is blurred into a four-level gaussian pyramid every frame; the floor shader unprojects the depth with the virtual camera to get each reflected surface's height above the floor and picks the pyramid level from that: the floor is near-mirror, the blur is 1.5 cm per metre of height and the image dims only a little, so the car reflects in its own colours; the floor's own colour must be passed to the `Reflector` constructor, which overwrites the shader's `color` uniform with a mid grey otherwise; around the car it reflects the studio instead: a faint 128×64 blurred copy of the HDRI plus the same four softboxes drawn analytically at their finite positions as elliptical blooms (not their rectangles: corners read as tiles on the floor), so the lights read as streaks on an otherwise dark floor; a tiled value-noise texture mottles tone and gloss), the key is a `SpotLight` high overhead (the only scene light; the paint's clearcoat roughness is 0.12, not a mirror, because a point light's highlight on the 26k-triangle glTF body lights one quad at a time and reads as a square sliding over the hood; even so the lobe was narrower than the normal varies across a triangle, so `sizeKeyFor()` patches every car material's shader to give the key a size, Karis's sphere-light approximation: the direct-light GGX alpha grows by `KEY_RADIUS / (2 · distance)`, no other scaling, so the same energy spreads over several triangles and the highlight dims and softens instead of popping on one; environment reflections are untouched), made visible by the `studio` group: an additive cone from the spot to its pool on the floor, soft at its silhouette and fading to nothing before the apex so no cut edge shows from any angle, hidden altogether as the camera climbs toward the spot, with 360 dust motes drifting down through it while frames flow; hidden from the reflection pass, contact shadow baked once the car is in, 4× MSAA + SMAA, a deliberately weak bloom at quarter res (anything stronger washes the headlamps white), ACES, camera presets with spherical fly-to (presets back off on narrow stages through `distanceScale()`, and `controls.maxDistance` follows it in `resize()`, or the first `controls.update()` after a fly-to snaps the camera in; `flyTo()` also zeroes the controls' easing deltas so a drag or pinch still decaying doesn't replay at the end), idle auto-rotate. A view can be sent as a link: once the camera rests after a drag or pinch, `writeCamHash()` puts `#cam=x,y,z,tx,ty,tz,fov` in the address bar, and `readCamHash()` starts the page on it (exactly: no stage scaling, no auto-rotate until the next touch); presets write nothing. For telling apart an artefact seen only on a real device, `&no=bloom,smaa,studio,key,env,msaa` on the hash leaves those stages out (the bloom, the SMAA pass, the beam and dust, the key light, the environment map, the post chain's 4× multisampling), and `&dpr=1.25` pins the starting pixel ratio (phones start at 2, desktops at 1.5; the old phone cap of 1.25 showed every canvas pixel as a 2.4-pixel block on a 3× screen, and fine highlights as flickering squares). Frames render only while the camera moves or `invalidate()` was called, paced by the display (no 60 fps cap; iOS Safari itself stays at 60 unless its 120 Hz feature flag is on); `[data-fps]` in the stage shows the measured rate and pixel ratio, or `idle`; `QUALITY` lists pixel-ratio / reflection-scale / bloom levels (phones 2 → 1.5 → 1 → 1 without bloom, desktops 1.5 → 1.25 → 1 → 1 without bloom) and the loop steps down a level when more than half of a 90-frame window runs under 30 fps. Imported materials get a roughness floor (0.28 opaque, 0.06 glass) because roughness-0 surfaces sparkle under the HDRI. The car is the glTF binary at `assets/models/model-3.glb`, loaded by `loadCar()`: the file's long axis is turned onto x, `GLB.nose` says which way it faces, it is scaled to the real length and stood on the floor, and the material named in `GLB.paintName` is swapped for our clearcoat paint so the swatches work. If the file is missing or fails to load, the procedural car from `model-3.js` is used instead.
- `assets/models/model-3.glb` — "Tesla model 3 2024" by brandonleong28 on Sketchfab, CC BY 4.0 (credited in the page copy and footer). 9 MB, 180k triangles, interior included, six PNG textures. Its material names are opaque (`Geo…Mtl`); the paint is `Geohoodsub00021Mtl`, the black trim and wheel faces `Georimblurlfsub01Mtl`, the glass the three `BLEND` materials. Nose along +x in the file.
- `assets/js/model-3.js` — the fallback car, built procedurally: the body is a loft of rounded cross-sections driven by longitudinal curves (`yTop`, `yBelt`, `zShoulder`, `zRoofEdge`, `zBumper`, arches), with per-face material regions (paint, glass, trim). Headlamps, tail lamps, the lower intake and corner vents are `facePatch` panels: grids in (y, z) that bisect the skin for x, so they sit flush on the nose or tail; trims are tubes along profile knots. Key stations: cowl at x = 0.85, windscreen header at −0.05, B-pillar cross member at −0.36 (the roof is glass from the cowl to the trunk lid, broken only there), rear glass base at −2.06, trunk edge at −2.27; front axle at x = 1.5, rear at −1.375; belt line ≈ 1.0 m; roof peaks at 1.441 m over the B-pillar; everything scaled to the published dimensions (4720 × 1850 × 1441 mm, 2875 mm wheelbase, 235/45 R18). Chrome delete: all trim is satin black. Wheels are the 18" Photon aero covers. `PAINTS` is the current Tesla palette.
- `assets/js/xingyue-l.js` — the previous car (Geely Xingyue L), same construction, kept for reference; nothing imports it.
- `assets/hdr/studio.hdr` — 1k studio HDRI from Poly Haven (CC0), used for image-based lighting on `/cars`.
- `assets/img/` — WebP images, pre-sized (phone screenshots 640px, logos 160px), plus the favicon and touch icon. The home page no longer uses any of them; the tools pages and 404 do. Convert new images with ImageMagick: `convert in.png -resize 1200x\> -quality 82 out.webp`.

## Conventions

- Nav and footer are duplicated verbatim in every page. Change them in all six HTML files (home, tools, device-mockup, cars, articles, 404; `linkedin/` is a bare redirect).
- Design language is deliberately restrained: black canvas, `--fg-2` grey for secondary text, one accent (`--link` / `--accent`), system font stack, backdrop blur only on the nav. Keep colour to the images.
- Animations are scroll-driven only. Elements with `.reveal` fade up once; `[data-parallax="0.1"]` moves relative to its parent; `[data-scrolly]` sections swap `[data-scene]` elements as `.step` elements cross the viewport centre; the home film plays from scroll position. Under `prefers-reduced-motion` the film still follows the scroll but nothing moves on its own, and every other animation is off.
- On the home page, `film.js` owns `opacity`, `transform` and `visibility` on `.cap` elements; don't animate them from CSS. To add a chapter: a `[data-ch]` section with `--len`, captions with `data-at`, a scene object in `film.js` (`draw(c, g, t, v, time)` and optional `sky`) appended to `scenes`, and a button in `.rail`. `.section--tint` is still available for other pages.
- Icons are inline SVG from Font Awesome Free (CC BY 4.0).
- `/cars` is the heaviest page. Keep it self-contained: three.js version pinned in the import map, no other libraries. To check it headlessly, serve the folder and screenshot with Playwright using Chromium's SwiftShader flags (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`); software rendering runs well under 1 fps there, so wait generously before screenshots.
- To check the home film headlessly, emulate `prefers-reduced-motion: reduce` so the playhead snaps to the scroll position, scroll to `chapterTop + t × (1 − vh / chapterHeight) × chapterHeight` for local progress `t`, and screenshot.
